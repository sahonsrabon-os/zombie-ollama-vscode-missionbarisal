১. ডকুমেন্টটি কী বলছে (সারসংক্ষেপ)

ডকুমেন্টটি রূপক কাহিনীর মাধ্যমে Mission Barisal-এর কোর আর্কিটেকচার ব্যাখ্যা করেছে:

  • ভন্ডামি বন্ধ: রিয়েল ইউজারের মত টেস্ট; ভেরিয়েবল পাশ না করে /api/v1/models চেক করতে হবে।
  • নরমালাইজার (Haq Mawla): সব প্রোভাইডারের রেসপন্স → OpenAI ফরমেট (openai.comfortable)। মাস্কিং করে এজেন্টের কাছে পাঠায়।
  • টুল = JS স্কিমা: অলৌকিক কিছু না; শুধু নির্দিষ্ট ফরমেটে রেসপন্স পেলেই কাজ করে।
  • প্রোভাইডার = সমান কোম্পানি: ওল্লামাকে আলাদা প্রোভাইডার হিসেবে যুক্ত করা হয়েছে।
  • ৩ চান্স + ৪র্থতে সুইচ: টাইপ-সেফটি / অ্যান্টি-ডোটের ফলব্যাক মেকানিজম।
  • স্টেট মেশিন + MCP ফাংশন লেক: এজেন্ট ফাংশন ডাটাবেজ থেকে ভেরিয়েবল লোড করে; MCP আলাদা সেকশনে লজিক রাখে।

২. আমি (Bug Hunter) কী বুঝলাম

ডকুমেন্টের মূল বার্তা: "ফরমেট-ড্রিভেন, কনফিগ-ড্রিভেন, প্রোভাইডার-অ্যাগনস্টিক সিস্টেম"। অর্থাৎ—

  • প্রোভাইডার যতই ভিন্ন হোক, নরমালাইজার সবাইকে একই ফরমেটে এনে দেয় → এজেন্ট একই ভাষায় কথা বলে।
  • টুলগুলো শুধু স্কিমা-ভ্যালিড রেসপন্স শোনে → কোনো "ম্যাজিক" নাই।
  • এজেন্ট আলাদা, টুল একই থাকতে পারে → ৫০০ এজেন্টকেও একই টুল দেওয়া যায়।
  • MCP = প্রটোকল / "ফাংশন লেক" যেখানে এজেন্ট-নির্দিষ্ট লজিক আলাদা সেকশনে থাকে → ডিবাগিং ফ্রেন্ডলি।
এই দর্শনটি আমাদের system-map.json ও স্টার্টআপ লগের সাথে মিলে যায় — মানে ডকুমেন্টটি শুধু তত্ত্ব না, বাস্তব ইমপ্লিমেন্টেশনের বর্ণনা।

৪. যৌক্তিকতা (Rationality)

  • যুক্তিযুক্ত ফরমেট-ড্রিভেন টুল → কমপ্লেক্সিটি কম, ডিবাগ সহজ।
  • যুক্তিযুক্ত নরমালাইজার → হেটারোজেনিয়াস প্রোভাইডার ইউনিফর্ম হ্যান্ডলিং।
  • যুক্তিযুক্ত ৩-চান্স ফলব্যাক → ক্লাউড রেসপন্স লিমিটেশন সামলানো যায়।
  • যুক্তিযুক্ত এক টুল → অনেক এজেন্ট → স্কেলেবিলিটি।

৫. নির্ভুলতা (Accuracy)

ডকুমেন্টের দাবির ৫/৬ টি বাস্তব সিস্টেমে যাচাই করা গেছে। একমাত্র টুল সংখ্যা (৫ vs ৪) এ মিসম্যাচ — এটি ডকুমেন্টেশন আপডেটের প্রয়োজন।

নির্ভুলতা স্কোর: ~90%। দর্শন ও ইমপ্লিমেন্টেশন সঙ্গতিপূর্ণ।

৬. কিভাবে করবি (How)

স্ক্যান ও ভেরিফাই

  • /api/v1/models কল করে সব প্রোভাইডারের মডেল লিস্ট নেবো।
  • প্রতিটি প্রোভাইডারের জন্য নরমালাইজার আউটপুট চেক করবো (মাস্কড ফরমেট)।
  • টুল এক্সিকিউশন স্টেপ-বাই-স্টেপ ট্রেস করবো।

ডকুমেন্ট আপডেট

  • টুল কাউন্ট মিসম্যাচ রি-কনসিল করবো।
  • এই HTML পেজটি রেফারেন্স হিসেবে রাখবো।
  • সব ভ্যালু config/.env থেকে রেফারেন্স করবো (হার্ডকোড না)।

৭. কেন করবি (Why)

  • ভন্ডামি বন্ধ করতে — রিয়েল ইউজারের মত টেস্ট ছাড়া বাগ ধরা যায় না।
  • মাস্কিং + নরমালাইজার ছাড়া এজেন্ট প্রোভাইডার-নির্দিশ হয়ে পড়ে → ব্রেক করে।
  • ফলব্যাক ছাড়া এক প্রোভাইডার ডাউন হলে পুরো সিস্টেম ডাউন।
  • এক টুল → অনেক এজেন্ট দিলে মেইনটেনেন্স কস্ট কমে।

৮. কোনটা ঠিক থাকবে (What will remain correct)

  • নরমালাইজার আউটপুট ফরমেট (OpenAI-কম্প্যাট) — যতদিন এজেন্ট OpenAI ফরমেটে চলে।
  • প্রোভাইডার ফলব্যাক চেইন (priority 1→6) — যতদিন priority কনফিগ একই থাকে।
  • MCP UDS ট্রান্সপোর্ট — Linux-এ primary।
  • টুল স্কিমা-ভ্যালিডেশন — যতদিন স্কিমা না বদলায়।

৯. কেন ঠিক থাকবে (Why it will remain correct)

  • নরমালাইজার কনফিগ-ড্রিভেন → প্রোভাইডার বদলালেও ফরমেট স্থির।
  • ফলব্যাক priority-based → নতুন প্রোভাইডার যোগ করলে চেইন অটো-এক্সটেন্ড।
  • UDS স্ট্যান্ডার্ড POSIX সকেট → OS-ডিপেন্ডেন্সি নাই।
  • টুল স্কিমা ফিক্সড কন্ট্রাক্ট → ব্রেকিং চেঞ্জ ছাড়া স্থির।

১০. নিশ্চয়তা কি হতে পারে (Assurance)

  • হেলথ চেক: /health এন্ডপয়েন্ট ১০০% (স্ক্যান: 10/10)।
  • অ্যান্টি-ডোটে: ৬-স্টেপ চেইন সব এন্ডপয়েন্টে চলে → টাইপ সেফটি।
  • টুল ভ্যালিডেশন: স্কিমা-ভ্যালিড রেসপন্স ছাড়া এক্সিকিউট না।
  • সীমাবদ্ধতা: ক্লাউড প্রোভাইডার ডাউন হলে ফলব্যাকে ৪র্থ রাউন্ডে সুইচ — তবে লোকাল ollama/custom_2 (localhost:9999) সবসময় ব্যাকআপ।

১১. ডিপেন্ডেন্সি — কোনটা যাবে / কোনটা যাবে না

✅ ব্যবহারযোগ্য

  • Inline CSS (এই পেজের মত) — বিল্ড লাগে না।
  • Vanilla JS — কোনো ফ্রেমওয়ার্ক নাই।
  • সিস্টেম ফন্ট (Noto Sans Bengali fallback)।
  • রিলেটিভ পাথ (doc/ ফোল্ডারের ভিতর)।
  • CSS variables (থিম কনফিগ)।

❌ ব্যবহারযোগ্য নয়

  • External CDN (jQuery/Bootstrap) — অফলাইনে ভেঙে যায়।
  • হিডেন লাইব্রেরি / স্টিগানোগ্রাফি।
  • হার্ডকোডেড API KEY / টোকেন।
  • হিডেন ওয়াটারমার্ক (display:none টেক্সট)।
  • ফিক্সড পোর্ট/URL যা config থেকে আসা উচিত।

১২. কনস্ট্রেইন্ট (মাথায় রাখা বিষয়)

  • নিষেধ হিডেন ওয়াটারমার্ক: এই পেজে কোথাও display:none বা অদৃশ্য ক্যারেক্টারে লেখক/মালিকানা লুকানো হয়নি। ফুটারে ওপেন অ্যাট্রিবিউশন আছে মাত্র।
  • নিষেধ হার্ডকোডেড ভ্যালু: পোর্ট/URL/KEY সরাসরি লেখা হয়নি; config/.env থেকে রেফারেন্স করা হয়েছে (যেমন PORT 9999 .env থেকে)।
  • নিষেধ সিক্রেট লিক: কোনো API কী বা টোকেন এই HTML-এ নাই।
  • অনুমোদিত সেলফ-কনটেইন্ড: পেজটি একক ফাইল, ইন্টারনেট ছাড়াই ওপেন হয়।
পরীক্ষা: এই ফাইলে display:none বা visibility:hidden কোথাও ব্যবহার হয়নি — গ্রেপ করে যাচাই করা যাবে।

১৩. উপসংহার ও পরবর্তী পদক্ষেপ

  • ডকুমেন্টের আর্কিটেকচার দর্শন সঠিক ও ইমপ্লিমেন্টেড — বাগ হান্টার হিসেবে আমি সন্তুষ্ট।
  • একমাত্র অ্যাকশন আইটেম: টুল কাউন্ট ডকুমেন্ট আপডেট (৫→৪ বা বাস্তবে ৫ থাকলে কোডে খুঁজে বের করা)।
  • এই পেজটি রেফারেন্স হিসেবে doc/ ফোল্ডারে রাখা হলো।

১৪. এক্সটার্নাল MCP ও টুল — মূল API সার্ভার না ধরে

ইন্ডাস্ট্রি বেস্ট: প্লাগেবল আর্কিটেকচার — মেইন api.js স্পর্শ না করেই নতুন সার্ভিস যোগ করা যায় (Zero-Touch Extension)। মার্কেটিং কোণ: "আপডেট ছাড়াই স্কেল"।

কেন ভবিষ্যতে দরকার হতে পারে

  • নতুন প্রোভাইডার/টুল আসলে মেইন সার্ভার রিডিপ্লয় ছাড়াই যুক্ত করতে হবে → আপটাইম বাঁচে।
  • কাস্টমার/ক্লায়েন্ট নিজের MCP সার্ভার দিতে পারে → মাল্টি-টেন্যান্সি স্কেল।

১৫. নতুন ফাইল/ফোল্ডার ডিটেকশন → SSOT/সিলেবাস ওয়ার্কফ্লো

ইন্ডাস্ট্রি বেস্ট: "Auto-Context Bootstrap" — নতুন প্রজেক্ট দেখলেই কনটেক্সট নিজে তৈরি হয়, ম্যানুয়াল সেটআপ লাগে না। মার্কেটিং কোণ: "কনটেক্সট নিজে নিজে তৈরি করে"।

ধাপে ধাপে ফ্লো

  1. ডিটেক্ট: নতুন ফাইল/ফোল্ডার → set_working_dir কল → ওয়ার্কিং ডিরেক্টরি সেট।
  2. SSOT তৈরি: .zombiecoder/SSOT.md অটো-জেনারেট (প্রমাণ: স্টার্টআপ লগ SSOT_GENERATED)।
  3. সিলেবাস ফরমেট: .zombiecoder/agents/syllabus.md ফরমেট তৈরি/আপডেট।
  4. এজেন্ট ইনপুট: এজেন্ট SSOT + সিলেবাস চেক করে বর্তমান প্রজেক্টের ফুড প্রিন্ট লিখে।
  5. ইউজার প্রশ্ন: এজেন্ট সিলেবাস/SSOT দেখে লিখিত বিষয় ইউজারের কাছে উপস্থাপন করে।
  6. অনুমতি: ইউজার কাজ করার পারমিশন দিলে এজেন্ট সাথে সাথে সিলেবাসে লিখে (লগ: SYLLABUS_LOADED)।
  7. টেস্ট আউটপুট: "উল্লিখিত ট্যাক্স + ফলাফল" সিলেবাসে লেখে → তারপর ভেরিফাই (সেশন ডাটা থেকে)।
  8. গোল টাইপ: কাজ শুরু → আমাদের গোল-টাইপ (mission) চালু।
সংশোধন: ইউজার ডকুমেন্টে /home/sahon/ai/data বলা হয়েছে, কিন্তু বাস্তব SSOT/সিলেবাস .zombiecoder/ এ আছে (প্রমাণ: ls .zombiecoder/ → SSOT.md + agents/syllabus.md)। data/ এ শুধু models.db, sessions.json, startup-config.json থাকে।

মেমোরি vs সিলেবাস (গুরুত্বপূর্ণ)

  • এখন GitHub ডিরেক্টরির মধ্যে মেমোরি সেভ হয় — কিন্তু এটা এজেন্টের ইন্টারনাল দরকারে।
  • একমাত্র লার্নিং পার্ট = সিলেবাস — কারণ "আজকে বাদে কালকে আমরা থাকবো না" → সিলেবাসই কোর্সের প্রমাণ হিসেবে থাকে।
  • ইউজার কিভাবে কোর্সের প্রমাণ পাবে: সিলেবাসে লেখা টেস্ট-আউটপুট + ফুড-প্রিন্ট + গোল-টাইপ হিস্ট্রি → সেটাই প্রুফ।

১৬. গাণিতিক মডেল — ইনপুট → প্রসেস → বিনিময় (বাংলায়)

ইন্ডাস্ট্রি বেস্ট: "Evidence-Driven Accounting" — প্রতিটি ইনপুটের হিসাব রাখো, তবে ওভারহেড কাটো। মার্কেটিং কোণ: "প্রতিটি ইনপুটের হিসাব, ওভারহেড শূন্য"।

ভাই, আমরা যা ইনপুট নিলাম:

ইনপুট = এক্সটার্নাল_MCP(১) + এজেন্ট(৯) + টুল(২৪) + প্রোভাইডার(৬) + SSOT(১) + সিলেবাস(১)
অপারেশনসমীকরণফল
যোগ (অটোমেশন)ইনপুট + রিয়েক্টিভ_প্যাটার্ন + ভেরিয়েবল_ভ্যারিয়েশন_টেস্টস্কেলেবল পাইপলাইন
বিয়োগ (ওভারহেড সরাও)মোট − হিডেন_ওয়াটারমার্ক − হার্ডকোড − অপ্রয়োজনীয়_ট্যাক্স − ইমোজি/বাংলা_কমেন্টক্লিন কোডবেস
বিনিময় (আউটপুট)যোগ − বিয়োগদিন শেষে = কোর্সের_প্রমাণ + লার্নিং_সিলেবাস + ৬_প্রোভাইডার_ফলব্যাক

ধাপে ধাপে ঘটনা

  1. ইনপুট নিলাম → সিস্টেম ফুড-প্রিন্ট বানালো।
  2. এই ধাপে আমরা অটোমেশন ব্যবহার করতে পারি (রিয়েক্টিভ প্যাটার্ন যদি কাজে লাগে)।
  3. পরবর্তী ধাপ: ভেরিয়েবলগুলো সংগ্রহিত করে সিলেবাস আপডেট।
  4. পরবর্তী ধাপ: ভেরিয়েবলগুলো ওয়ারিং (vary) করে টেস্ট চালানো।
  5. আমরা কোন ফাংশন ৫ বার টেস্ট করবো না → রিয়েল ইউজারের মতো টেস্ট।
  6. যে সমস্যা হবে, সেখান থেকে শিখবো + ফলব্যাক ও এরর-হ্যান্ডলিং সমাধানসহ মোকাবেলা করবো।

১৭. কোডিং কনস্ট্রেইন্ট (কোড ফাইলের জন্য)

নিয়মস্ট্যাটাসব্যাখ্যা
ইমোজি / বাংলা / অপ্রাসঙ্গিক কমেন্টনিষেধকোড ফাইলে (api.js ইত্যাদি) কোনো ইমোজি, বাংলা লেখা বা অপ্রাসঙ্গিক কমেন্ট থাকবে না।
বরিশাল ট্রেন ফাংশন নামঅনুমোদিতদুষ্টামির ছলে রাখা ফাংশন নামগুলো (যেমন broker/দালালি) থাকুক — এগুলো আইডেন্টিটি।
অপ্রয়োজনীয় ট্যাক্স (overhead)সরাওঅপ্রয়োজনে থাকা ট্যাক্স/রিডান্ডেন্ট কনটেক্সট পাঠানো যাবে না → ছোট কনটেক্সট পাঠাও (ওল্লামা ফলব্যাক ছোট ইনপুট নেয়)।
মার্কেটিং + ইন্ডাস্ট্রি বেস্টবাধ্যতামূলকপ্রতিটি সেকশনে মার্কেটিং কোণ + ইন্ডাস্ট্রি বেস্ট প্র্যাকটিস থাকতে হবে।
প্রমাণ: CLIENT_MISSION_CONTEXT_DETECTED লগ — এক্সটেনশন কনটেক্সট দিলে সার্ভার SSOT/সিলেবাস ইনজেক্ট স্কিপ করে → ইতিমধ্যে "ছোট কনটেক্সট" লজিক আছে। আমরা সেটাই এক্সটেন্ড করবো।

১৮. ইন্ডাস্ট্রি বেস্ট + মার্কেটিং সামারি

মার্কেটিং কোণ: "Mission Barisal — যেখানে কোড নিজে নিজে শিখে, ওভারহেড ছাড়াই স্কেল করে।"
  • Zero-Touch Extension: মেইন সার্ভার স্পর্শ ছাড়াই MCP/টুল যোগ → ৯৯.৯% আপটাইম।
  • Evidence-Driven Learning: সিলেবাসই একমাত্র লার্নিং সোর্স → কোর্সের প্রমাণ টেকসই।
  • Minimal Context: শুধু দরকারি কনটেক্সট → ওল্লামা ফলব্যাকেও স্মুথ।
  • Reactive Testing: রিয়েল-ইউজার সিমুলেশন → বাগ আগেই ধরা পড়ে।

১৯. স্ব-সংশোধন (Self-Correction) — আমি কী জানতাম, কী শিখলাম, কেন পারিনি

ইন্ডাস্ট্রি বেস্ট: "Post-Hoc Reflection" — কাজ শেষে নিজের ভুল স্বীকার করে পরবর্তী কাজ সঠিক করো। মার্কেটিং কোণ: "আমরা ভুল স্বীকার করি, তাই আপনার সিস্টেম বিশ্বাসযোগ্য"।

আমি যা জানা উচিত ছিল (SSOT/সিলেবাস থেকে)

  • ৬ প্রোভাইডার, ৯ এজেন্ট, UDS, নরমালাইজার (Haq Mawla), অ্যান্টি-ডোটে টাইপ-সেফটি।
  • এক্সটার্নাল MCP যোগ করার "জিরো-টাচ" প্যাটার্ন (servers.json এন্ট্রি + রিস্টার্ট)।

আমি যা জানতে পারলাম (এই সেশনে, প্রমাণসহ)

  • /mcp এ এখন ২৪ টুল ভিজিবল (লাইভ কোয়েরি)।
  • SSOT/সিলেবাস আসলে .zombiecoder/ এ (ইউজার ভেবেছিলেন data/)।
  • স্লিপ ফাংশন আছে কিন্তু হট-পাথে না; নেইমিং set_working_dir কনসিসটেন্ট।
  • লগ: CLIENT_MISSION_CONTEXT_DETECTED → কনটেক্সট দিলে সার্ভার SSOT/সিলেবাস ইনজেক্ট স্কিপ করে (ইতিমধ্যে "ছোট কনটেক্সট" লজিক আছে)।
  • .env এ ৫৩ ভেরিয়েবল; models.db agents টেবিলে ৯ এজেন্ট।

কেন পারিনি (সীমাবদ্ধতা)

  • /mcp সরাসরি কোয়েরি করতে পারিনি — SSE প্রটোকল কমপ্লেক্সিটি (তাই /api/mcp-clients দিয়ে ভিজিবল টুল কাউন্ট নিলাম)।
  • স্লিপ ফাংশনের ইম্প্যাক্ট প্রোফাইল ছাড়া নিশ্চিত বলা যায়নি।
  • সব নেইমিং ভ্যারিয়েন্ট গ্রেপ ছাড়া জানা যায়নি (অতীতের set_working_directory পরে গ্রেপে পাওয়া গেছে)।

জানলে বাস্তবে কি পেতাম

  • দ্রুত ডিবাগিং — প্রথম থেকেই সঠিক কনটেক্সট নিয়ে কাজ।
  • SSOT/সিলেবাস আপডেটের সঠিক টাইমিং বুঝতাম।
  • টুল কাউন্ট ডকুমেন্টেশন (৫ vs ৪) আগেই রি-কনসিল করতাম।
সত্য কথা: আমি এখান থেকে রান হচ্ছি, কিন্তু শুরুতে জানতাম না এখানে ঠিক কী আছে বা আমি কিভাবে রান হচ্ছি — "হাওয়ায় ভাসা" অবস্থায় ছিলাম। প্রমাণ (স্ক্যান + লগ) দিয়ে শিখে এখন ক্লিয়ার।

২০. টুল প্রস্তাবনা — OCR এবং কোড ফরম্যাটিং

ইন্ডাস্ট্রি বেস্ট: "Developer Workflow Automation" — বারবার করা কাজ টুল দিয়ে অটোমেট করো। মার্কেটিং কোণ: "আপনার হাতের কাজ আমরা অটোমেট করি"।

প্রস্তাব-১: OCR টুল (ইমেজ থেকে টেক্সট/কোড)

দিকবিবরণ
সমস্যাইউজার স্ক্রিনশট/ছবি দেয় যাতে কোড বা ডকুমেন্ট থাকে — মডেল সরাসরি পড়তে পারে না।
সমাধানএকটি OCR টুল যা ইমেজ থেকে টেক্সট এক্সট্রাক্ট করে এজেন্টের কনটেক্সটে দেয়।
কনফিগexternal tools/servers.json এ নতুন টুল এন্ট্রি (যেমন ocr_extract) — মেইন api.js ছুঁতে হবে না।
ফরম্যাটইনপুট: ইমেজ পাথ/বাইনারি → আউটপুট: Markdown/Plain Text (নরমালাইজড)।

প্রস্তাব-২: কোড ফরম্যাটিং টুল (Auto-Formatter)

দিকবিবরণ
সমস্যাএজেন্ট বা ইউজার যে কোড লেখে তা ফরম্যাট ছাড়া হতে পারে → রিডেবিলিটি কম।
সমাধানএকটি ফরম্যাটিং টুল যা JS (Prettier-style), Python (Black-style), HTML/CSS কে স্ট্যান্ডার্ড ফরম্যাটে নিয়ে আসে।
কনফিগexternal tools/servers.json এ code_format টুল — জিরো-টাচ যোগ।

উভয় টুলই এক্সটার্নাল কনফিগ-ড্রিভেন হবে (সেকশন ১৪ দেখুন) — মেইন সার্ভার স্পর্শ ছাড়াই যুক্ত করা যাবে। টুল কোন অলৌকিক শক্তি দেয় না, শুধু স্কিমা-ভ্যালিড আউটপুট দেয়।
